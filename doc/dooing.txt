1. Dooing                                                        *dooing-intro*

A minimalist todo list manager for Neovim, designed with simplicity and
efficiency in mind. It provides a clean, distraction-free interface to manage
your tasks directly within Neovim.

FEATURES                                                      *dooing-features*

- 📝 Manage todos in a clean floating window
- 🏷️ Categorize tasks with #tags
- ✅ Simple task management with clear visual feedback
- 💾 Persistent storage of your todos
- 🎨 Adapts to your Neovim colorscheme
- 📅 Due dates with calendar integration
- ⚡ Priority system with customizable weights
- 🔍 Search and filter capabilities
- 📤 Import/Export functionality
- 🔄 Undo/Redo support for deleted todos

REQUIREMENTS                                              *dooing-requirements*

- Neovim >= 0.10.0
- A patched font for icons (recommended)
- Optional: nvim-web-devicons for file icons

INSTALLATION                                              *dooing-installation*

Using lazy.nvim: >lua
    {
        "atiladefreitas/dooing",
        config = function()
            require("dooing").setup({
                -- your configuration here
            })
        end,
    }
<

CONFIGURATION                                            *dooing-configuration*

The plugin can be configured by passing a table to the setup function:
>
    require('dooing').setup({
        ui = {                             -- See |dooing-modern-ui|
            style = "classic",             -- "classic" | "modern"
            sections = true,               -- status headings with counts
            priority_bar = true,           -- colored marker per row
            tree_connectors = true,        -- tree guides for nested tasks
            note_preview = true,           -- first notes line beneath the todo
            progress = true,               -- progress bar in the title
            compact_quick_keys = true,     -- single-strip quick keys
        },
        window = {
            dimensions = {             -- Size of the todo window; may also be
                width = 55,            -- a function returning a table with
                height = 20,           -- these keys, see
            },                         -- |dooing-adaptive-size|
            border = "rounded",        -- Border style
            zindex = 50,               -- Base z-index for floating windows
                                       -- Dooing uses zindex to zindex+5 for layering:
                                       -- +0: main window, quick keys
                                       -- +1: scratchpad
                                       -- +2: due notification
                                       -- +3: help, tags, search
                                       -- +4: calendar, priority picker
                                       -- +5: delete confirmation
            position = "right",        -- Window position: "right", "left", "top", "bottom", "center",
                                       -- "top-right", "top-left", "bottom-right", "bottom-left"
            padding = {
                top = 1,
                bottom = 1,
                left = 2,
                right = 2,
            },
        },
        quick_keys = true,
        formatting = {
            pending = {
                icon = "○",
                format = { "icon", "text", "due_date", "ect" },
            },
            done = {
                icon = "✓",
                format = { "icon", "text", "due_date", "ect" },
            },
        },
        priorities = {
            {
                name = "important",
                weight = 4,
            },
            {
                name = "urgent",
                weight = 2,
            },
        },
        save_path = vim.fn.stdpath("data") .. "/dooing_todos.json",
        calendar = {
            language = "en",
            start_day = "sunday",  -- or "monday"
            icon = "",
        },
    })
<

MODERN UI                                                  *dooing-modern-ui*

Dooing ships a redesigned interface behind `ui.style = "modern"`. It is
opt-in: the default "classic" style renders exactly as it always has, so
updating the plugin never changes your interface.
>
    require('dooing').setup({
        ui = { style = "modern" },
    })
<
The modern style changes the following:

- Status sections. Top-level todos are grouped under IN PROGRESS, PENDING and
  DONE, each with a count. Subtasks always stay under their parent, so a
  nested tree is never split across sections.
- Priority as a marker. Only the marker and the status icon carry the
  priority color, instead of tinting the whole row.
- Right-aligned dimmed metadata. Estimate, due date and age sit on the right
  of the row, or move to their own dimmed line when the row would be
  squeezed.
- Tree connectors for nested tasks.
- Note previews. A todo's description is stored in its notes, edited in the
  scratchpad (`open_todo_scratchpad`, `<leader>p` by default). The first line
  is shown beneath the todo, dimmed and aligned with the text, truncated with
  an ellipsis when it does not fit. Every line a todo occupies resolves back
  to that todo, so keys work from the note line too. Set
  `ui.note_preview = false` to show only the notes indicator icon.
- Sharper due dates: "overdue 3d" in red, distinct accents for "due today",
  "due tomorrow" and "in 5d", plain dates further out.
- Progress bar in the window title and an overdue count in the footer.
- A width-adaptive quick keys strip instead of the fixed 8-line panel.
- Folding by the todo's real nesting depth, so `zc` on a parent collapses
  exactly its own subtree. The classic style folds on character indent, which
  has no effect unless 'shiftwidth' happens to be small.

Sub-windows~

Every secondary window is centered on the editor and sized from its own
content, rather than positioned against a hard-coded guess at the main
window's width:

- Prompts (new to-do, sub-task, edit, time estimation, tag rename, search)
  open a centered input box in insert mode instead of using the cmdline.
  Import and export keep using |vim.ui.input()| because they rely on
  filename completion.
- The help window is grouped by what the keys do, aligns the key column
  across all groups, and omits any keymap set to `false`.
- The tags window shows how many todos carry each tag.
- Search prompts in the centered input, highlights the matched text in the
  results, and reports the result count in the footer. Pressing <CR> jumps
  to the todo, first clearing an active tag filter if it would hide it.
- The calendar is centered with its navigation keys shown in the footer, and
  uses a roomier grid than the classic one (32x10 rather than 26x9): wider
  day cells, with the weekday names separated from the days by a blank line.

Each of these has its own toggle under `ui`, so they can be mixed and
matched. Every toggle additionally requires `ui.style = "modern"`, so the
classic layout is never affected:
>
    require('dooing').setup({
        ui = { style = "modern", tree_connectors = false },
    })
<
Section titles and icons can be customised:
>
    require('dooing').setup({
        ui = {
            style = "modern",
            section_titles = {
                in_progress = "DOING",
                pending = "TODO",
                done = "DONE",
            },
            icons = {
                priority_bar = "▎",
                overdue = "󰀦",
                progress_on = "▰",
                progress_off = "▱",
            },
        },
    })
<
All colors are highlight groups with default links, so a colorscheme or your
own configuration can override any of them. See |dooing-colors|.


ADAPTIVE WINDOW SIZE                                    *dooing-adaptive-size*

`window.dimensions` accepts either a table or a function returning one. The
function is evaluated every time the todo window is opened, so the size can
adapt to the current editor dimensions:
>
    require("dooing").setup({
        window = {
            dimensions = function()
                return {
                    width = math.max(40, math.floor(vim.o.columns * 0.4)),
                    height = math.max(10, math.floor(vim.o.lines * 0.6)),
                }
            end,
        },
    })
<
Values are floored and clamped to the space available in the editor. If the
function raises an error or returns something unusable, Dooing falls back to
`{ width = 55, height = 20 }`.

The former `window.width` and `window.height` options are deprecated but still
honoured: they are folded into `window.dimensions` (with a warning) so that
existing configurations keep working.


USAGE                                                          *dooing-usage*

Basic Operations:
1. Open the todo window with `:Dooing`
2. Add new todos with `i`
3. Toggle completion with `x`
4. Delete todos with `d`
5. Add due dates with `H`
6. Add priorities during creation
7. Filter by tags with `t`

COMMANDS                                                      *dooing-commands*

                                                                    *:Dooing*
Main command to interact with the plugin.

Arguments:~
    none            Opens/toggles the todo window
    add [text]      Creates a new todo
    list            Lists all todos in the command line
    set             Modifies todo properties

Examples: >vim
    :Dooing
    :Dooing add My new task #work
    :Dooing add -p important,urgent My priority task
    :Dooing list
    :Dooing set 1 priorities important,urgent
<

KEYBINDINGS                                                *dooing-keybindings*

Main Window~
    <leader>td   Toggle todo window
    i           Add new todo
    x           Toggle todo status
    d           Delete current todo
    D           Delete all completed todos
    q           Close window
    H           Add due date
    r           Remove due date
    T           Add time estimation
    R           Remove time estimation
    ?           Toggle help window
    t           Toggle tags window
    c           Clear active tag filter
    e           Edit todo
    p           Edit priorities
    u           Undo deletion
    /           Search todos
    I           Import todos
    E           Export todos
    <leader>D   Remove duplicates
    <Space>     Toggle priority
    <leader>p   Open todo scratchpad
    f           Refresh todo list
    s           Share todos

Tags Window~
    e           Edit tag
    d           Delete tag
    <CR>        Filter by tag
    q           Close window

Calendar Window~
    h           Previous day
    l           Next day
    k           Previous week
    j           Next week
    H           Previous month
    L           Next month
    <CR>        Select date
    q           Close calendar

2. Advanced                                                    *dooing-advanced*

CALENDAR                                                     *dooing-calendar*

The calendar feature supports multiple languages and provides a visual way to
set due dates. Supported languages: en, pt, es, fr, de, it, jp

You can configure the start day of the week in the calendar by setting `calendar.start_day` to either `"sunday"` or `"monday"`. Any other value will default to `"sunday"`.

Configure the calendar: >lua
    calendar = {
        language = "en",  -- Calendar language
        start_day = "sunday",  -- or "monday"
        icon = "",      -- Icon for due dates
        keymaps = {
            previous_day = "h",
            next_day = "l",
            previous_week = "k",
            next_week = "j",
            previous_month = "H",
            next_month = "L",
            select_day = "<CR>",
            close_calendar = "q",
        },
    }
<


PRIORITY SYSTEM                                             *dooing-priorities*

Configure priorities and their weights: >lua
    priorities = {
        {
            name = "important",
            weight = 4,
        },
        {
            name = "urgent",
            weight = 2,
        },
    },
    priority_groups = {
        high = {
            members = { "important", "urgent" },
            hl_group = "DiagnosticError",
        },
        medium = {
            members = { "important" },
            hl_group = "DiagnosticWarn",
        },
    }
<

IMPORT/EXPORT                                                 *dooing-import*

Import and export todos using JSON format: >vim
    :Dooing export ~/todos.json
    :Dooing import ~/todos.json
<

3. Colors                                                      *dooing-colors*

All groups are defined as `default` links, so a colorscheme or your own
`nvim_set_hl()` call always takes precedence:
>
    vim.api.nvim_set_hl(0, "DooingSectionTitle", { fg = "#89b4fa", bold = true })
<
Highlight Groups~
`DooingPending`       Pending todo items          (link: Question)
`DooingDone`          Completed todo items        (link: Comment)
`DooingHelpText`      Help window text            (link: Directory)
`DooingTimestamp`     Relative timestamps         (link: Comment)
`DooingQuickTitle`    Quick keys title            (link: Title)
`DooingQuickKey`      Quick keys keybindings      (link: Identifier)
`DooingQuickDesc`     Quick keys descriptions     (link: Comment)

Used by the modern style, see |dooing-modern-ui|:
`DooingText`          Todo text                   (link: Normal)
`DooingMeta`          Estimates, ages, dates      (link: Comment)
`DooingTag`           #tags                       (link: Type)
`DooingSectionTitle`  Section and window titles   (link: Title)
`DooingSectionCount`  Section counts, progress    (link: Comment)
`DooingSectionRule`   Section separator rule      (link: NonText)
`DooingTreeGuide`     Nested task connectors      (link: NonText)
`DooingOverdue`       Overdue due dates           (link: DiagnosticError)
`DooingDueToday`      Due today                   (link: DiagnosticWarn)
`DooingDueSoon`       Due within a week           (link: DiagnosticInfo)
`DooingProgressOn`    Filled progress cells       (link: DiagnosticOk)
`DooingProgressOff`   Empty progress cells        (link: NonText)
